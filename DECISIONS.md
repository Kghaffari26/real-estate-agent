- An unusable single LLM response (`LLMError`: refusal/truncation/schema mismatch) falls back to the template instead of failing the run; API/auth errors and `BudgetExceeded` still fail it (CLAUDE.md: the LLM path has no optional-source exemption).

- National construction series now share one date-aligned `dates` array over the last 36 months (§6 rule: all series share one dates array); before, `dates` came from housing starts only and both series held FRED's full history since 2000.
- Index size overflow now drops `national.series` down to the core 6 metrics (§10 says "beyond the core 6"; the old code kept only 2), then fails with `PublishSizeError`; size is measured with a representative agents-core meta block since the runner adds meta after `analyze`.

The Census API now requires `CENSUS_API_KEY`, which this environment lacks, so affordability's `payment_to_income` stays null here (listed as a manual step).

## Session 4 (2026-09-27): agents-core v0.3.0, investigator, evals, tracing

- Pinned agents-core with `tag = "v0.3.0"` (uv wrote `rev =`; switched to `tag` to match the README and the previous pin).
- Deleted `agents/real_estate/download.py` for `Http.download` (same `<dest>.meta.json` sidecar keys, so existing downloads stay conditional); its 3 unit tests became one wiring test, since agents-core now tests the helper.
- ACS income uses `http.get_json` with the normal TTL cache instead of `http.get(ttl_seconds=0)`: v0.2.0 never caches non-JSON bodies and keys the cache on which secrets were sent.
- Warnings go through `ctx.warn` (published as `meta.warnings`); `Fetched.warnings` is the same list object, so `--dry-run` still prints them. `state.json` lost `last_run`; there's no separate `batch_fallback` field, just a warning.
- Batch timeout uses `batch(on_timeout="sync", max_concurrency=5)` (§7.4's concurrency 5), replacing the local sequential fallback.
- Removed `data/real_estate/briefs.json`, since v0.2.0 restores the `data` branch: briefs and investigations are reused from the previous published output when `state.json`'s hash matches. Consequence: a local checkout without `public-data/` regenerates everything (~$0.06), and so will the first CI run, because this repo has no `data` branch yet.
- The other listed v0.2.0 workarounds had no local counterpart here: no HTTP daily caps (FRED/Census use rate limits only), no token passthrough (this agent reads no GitHub token), and no per-tier temperature (none set). Nothing to remove.
- The workflow grants only `contents: write`: the agent never calls `ctx.alert`, so `issues: write` isn't needed. `cache_path` stays `data/cache/real_estate` (downloads), never `public-data`.
- No API key → `llm_available()` (building the SDK client raises without a key) → templates for every new brief and investigation, status ok, one warning. Their hashes are *not* stored, so the first run with a key regenerates them with the LLM. An injected test client counts as available.
- delta formats: day differences → `count_signed`, month differences (months of supply) → `decimal1` (agents-core has no signed one-decimal format; negatives still show their sign), pp differences → `pp_signed`. `MetricValue.delta_format` is typed as agents-core's `StatFormat`, so a non-standard value fails validation.
- Alert groups: the label is the flag's configured threshold (`flags.group_label`) and the severity is the group's highest; per-metro figures go in an additive `alerts[].metros` (slug, name, own label, value rounded to 4 places, severity). `slugs` is kept unchanged for existing consumers.
- State file (and the ACS income cache) moved under `settings.data_dir()`. The Redfin/Zillow download cache stays at `data/cache/real_estate` because the workflow's `cache_path` names it.
- Index size: the check now includes `meta.warnings` (previously omitted) with a 512-byte margin, and §10's trimming is `fit_index()`, unit-tested. The first live run still failed at 154,755 bytes: §10's trimming only saves ~2 KB, and 129 KB of the index was `metros[].latest` serializing 7 always-null `MetricValue` fields. The index now uses `MetricSummaryValue {value, yoy}`, exactly §6.1's shape (85 KB). This drops keys that were always null; treated as conformance, not a §6 change.
- `schema_version` 1.0.0 → 1.1.0: investigations, alert figures and meta.warnings are additive fields with defaults.
- Investigator "new major flag" = major now and not major one month earlier, recomputed from the data minus its last month (only `inventory_surge` and `price_decline` can be major). This is deterministic and needs no run history, so re-running on the same data selects the same targets and reuses them. "Top mover" = largest absolute median-price YoY.
- "Same region" = Census Bureau region of the metro's first state (from its name). Peers are the 5 closest by `homes_sold_12m` in that region, excluding the metro itself.
- Investigator on the fast tier (Haiku 4.5): with $0.05 per investigation and 8 steps, one smart-tier worst-case call (~$0.03 at 1,200 output tokens with a growing context) leaves no room for a second step. Live investigations take 3–4 steps and cost $0.014–0.025.
- Investigation reuse hash = the whole investigator snapshot + target + prompt version. A rate change therefore reruns investigations (their explanations can cite rates), unlike metro briefs. A prompt-version bump reruns only the investigations.
- Guard facts for the investigator are the task facts plus every tool output returned so far, rebuilt at each `finish` (fields_guard collects numbers when it's built). Citations of metrics the model never retrieved are dropped; if none are left, the trigger metric is cited.
- `finish` rejects computed multiples ("4.3 times", "3x", "twice", "three times") after a live explanation computed 7.8/1.8 and the guard passed it by coincidence. It accepts false positives like "5 times in a row"; the model just rephrases.
- The investigator's sentence counter treats "St.", "Ft.", "Mt.", "U.S." as non-terminal, so "St. Louis" doesn't break the 4–6 sentence check.
- Evals: suites live in `evals/real_estate/suites.py` (importable through the editable install). `python -m evals.real_estate.run` stays as a shortcut for the free suite. The LLM brief suite runs the production prompt synchronously, not through the batch (same prompt, guard and fallback), so it's per-case and cheap.
- Investigator eval fixtures are a live snapshot (27 metros: 6 targets and their peers), not synthetic. Cases reuse real flag labels; two are labelled `new_major_flag` although the flag was `notable` this month. The case tests the prompt path, not the selection rule (which has unit tests). The "forbidden tool" case removes rate data, so `get_rate_history` isn't offered and must not be called.
- The LLM judge isn't calibrated against human labels yet: the only labels available would have been written by this session, which isn't a human baseline. Left as a STATUS item; the judge's scores are reported as-is (0.917 → 0.833 → 0.833 across prompt changes, within noise for 6 cases).
- Eval gate: `regression_threshold` 0.10 rather than the default 0.05, because one judge step on one of 6 cases moves the mean by 0.042. $0.25 cap per suite (a full investigator run is ~$0.13).
- Recorded the 6 investigator trajectories from the live eval run and replay them in pytest with `ReplayClient(strict=True)`. They're re-recorded whenever the eval runs with `RE_SAVE_TRAJECTORIES`.
- Pushed to `main` as asked, fast-forwarding from the session branch `claude/hopeful-ride-1go4a0`, which was pushed as well.
